# 综合管理 AI 智能助手：产品设计与参赛演示

这是一套面向企业综合管理岗位的智能体搭建比赛产品，聚焦经营管理赛道的降本增效，把《综合管理 AI 智能助手》中的设想收敛为一个可以操作、导出和展示的 Web 工作台。原始方案文档不随项目公开；仓库和页面使用虚构示例资料。

## 1. 用一条完整业务线讲清价值

主线是“一场会议从准备到落实”：整理人员与议程 → 确认排序 → 编排席位 → 生成会议材料 → 整理纪要 → 人工审核 → 建立督办。

原方案范围较大，参赛时以会务闭环为重点，公文和政务信息作为同一资料复用的延伸，知识库作为材料来源。这样可以展示从重复录入到成果交付的实际变化，不需要商业化定价、客户系统或复杂组织架构。

### 智能体如何完成经营管理任务

工作人员给出业务目标，例如“整理本次会议的参会顺序、检查议程，生成五类材料”。智能体读取当前会议和人员的基础资料，由模型选择必要的工具及执行顺序，网页执行实际本地操作，并展示过程。模型不会因输出一个计划就把任务标记为完成。

六个工具分别是查找人员、整理参会顺序、检查会议议程、生成会务材料、整理会议纪要、提取督办事项。工具范围明确，能映射到页面中可以检查的业务成果。工具参数仅允许说明业务理由，模型不能注入任意代码、接口或未经确认的数据更改。

会务材料生成前必须暂停，等待工作人员核对并确认排序；督办事项形成前必须暂停，等待纪要人工审核。相关资料改变时，之前的确认需要重新核对。不能通过工具完成的外部发送、真实审批等目标会提示调整，不承诺已执行。

## 2. 四个模块与职责

### 会务助手：主展示场景

- **人员**：整理参会信息，提示缺失与重复项，给出可调整的排序；工作人员核对后明确确认。单位、姓名、职务或顺序等相关内容发生变化，之前的排序确认失效，重新确认后再形成正式材料。
- **议程**：编辑会议时间、地点、议题、主持人与发言安排；缺失信息明确显示待确认。
- **座位**：根据已确认人员进行席位编排，展示会议室及圆桌场景，允许人工调整。排序和席位均是会务人员确认的建议，不宣称具备企业礼宾规则的权威判断能力。
- **材料**：对应原方案的 5 项成果：参会名单、会议议程、会议手册、名签（桌签、饭签）、座位图（会议室、圆桌）。材料与当前会议资料关联，导出前完成确认。
- **纪要与督办**：输入会议记录，获得可编辑纪要草稿；核对决议、责任人、截止日期后审核，再将明确的待办录入本地督办列表。责任人或日期没有依据时，保持“待确认”。

会前准备清单可以作为辅助提示。二维码签到、会议室预约与“PPT 预先导入 Pad”依赖企业系统，保留接入规划，不在演示里声称已经执行。

### 政务信息：可追溯的人工审核

流程是候选信息 → 文字与材料一致性检查 → 事实人工核实 → 主任审阅 → 审核通过 → 导出报送材料包。

AI 可以标出表达问题、材料冲突与缺失依据，不能把“材料内一致”判断成“新闻真实”。主任审阅与审核通过是演示中的人工状态操作；导出报送材料包后，由工作人员在企业正式渠道处理。本项目没有接入石化通，也不提供真实报送回执。

### 公文助手：减少起草与校对的重复工作

按文种和工作需求生成草稿、核对措辞及格式，再编辑和导出。时间、文号、数据、引用依据等缺失字段保留待确认标记。用户始终可以直接修改内容，生成结果不会自动代表单位发布或完成审批。

### 知识库：小范围、可解释的资料复用

支持在当前浏览器中维护、搜索常用资料和人员信息。来访资料延续原方案的思路：历史接待记录、单位及职务变动、经授权的接待注意事项与饮食忌口。参赛数据应使用虚构信息；正式落地时只维护工作必需且获得授权的内容。

当前知识库是可检索的浏览器本地资料。它没有连接企业文档库、员工目录或检索增强服务，不声称自动获得内部制度全文。

## 3. 三层实现边界

**可直接演示的静态产品。** 页面操作、人工确认、材料编排、导出和状态变化在浏览器中运行；业务数据保存于当前浏览器的 localStorage。重新打开同一来源的页面可恢复本地资料，换设备、换浏览器、清除网站数据后不会自动同步。页面角色用于展示分工，不是服务端权限控制。

**可选的真实模型调用。** 配置独立转发服务后，智能体通过 DeepSeek 的 function calling 选择工具，同时可辅助生成纪要、公文和信息检查内容。转发服务只接受六个工具，检查重复步骤、先后依赖和参数格式；浏览器再执行计划，并在关键节点等待人工确认。网页不保存 DeepSeek API 密钥；转发服务从服务端环境变量读取密钥。连接口令只在网页当前会话中保存。未配置服务时，用规则和示例内容完成比赛演示，并明确标识演示模式。

**尚未连接的企业系统。** 企业单点登录、多人数据库、服务器审计、文件权限、组织通讯录、会议室、签到、Pad、石化通、生产级工作流都属于后续接入。原方案出现的“DeepSeek Harness”没有给出具体 SDK 或接口定义，本项目不将它作为已经完成的技术组件。

GitHub Pages 适合托管使用虚构资料的参赛展示页。它本身不提供企业内网访问控制；正式内部上线需要企业提供合适的托管环境、身份验证及数据存储。

## 4. 五分钟演示脚本

1. **0:00–0:45，给智能体一个目标。** 打开示例工作台，输入“整理本次会议参会顺序、检查议程并生成材料”，说明要为一次经营协调会做准备。查看工具计划及调用过程，明确当前是示例模式还是真实 DeepSeek 模式。
2. **0:45–1:40，完成会前准备。** 智能体运行到人工确认节点后，打开人员名单，修改一项职务或顺序，展示“需要重新确认”的状态；确认后继续运行，查看议程、会议室席位和圆桌布局。
3. **1:40–2:30，拿到具体成果。** 查看并导出参会名单、议程、手册、名签和座位图中的代表产物，强调资料变化会影响材料生成，工作人员保留最后确认权。
4. **2:30–3:30，从纪要走向落实。** 使用一段虚构会议记录生成或整理纪要，补充待确认字段，人工审核后建立督办；更新一条任务进展，说明目前保存在本机。
5. **3:30–4:30，演示信息报送。** 检查一篇候选稿，查看依据不足提示，人工核实、主任审阅、通过后导出材料包；明确最后的正式报送仍由工作人员执行。
6. **4:30–5:00，说明降本增效的验证方法。** 展示公文与知识库，说明同一会议背景可以复用到后续工作。结合实际用时记录解释减少了哪些重复录入和材料整理步骤，说明真实模型通过单独服务接入。

不要把一遍演示的速度直接写成真实节省工时或准确率。先邀请同事按原流程和智能体辅助流程各完成同样的虚构会务任务，分别记录人员整理、议程核对、五类材料制作、纪要整理和任务录入的主动工作分钟数，保留审核及修改的耗时。再比较总用时、返工次数和材料遗漏数，并标明样本量。

年度节省工时可按“每次实测减少的分钟数 × 年会议次数 ÷ 60”估算；工时成本估算需注明采用的小时成本，不能直接等同于财务现金节省。尚未实测时，页面参数和演示数字均作为可调整的测算假设，不写成已实现的降本比例或收入成果。

## 5. 下一步只做必要的企业落地

先由使用者确认 5 项会务材料的实际样式、排序规则和审批环节，再选择一种企业认可的托管方式。接着补齐账号权限、多人持久化、服务端审核记录及文件存储，最后按优先级连接通讯录、会议室和正式报送系统。保留人工审核节点，让模型负责起草和查漏，关键业务状态由明确操作改变。
