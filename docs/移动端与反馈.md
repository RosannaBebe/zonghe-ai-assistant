# 移动端与用户反馈

知行综合管理 AI 智能助手支持在手机浏览器中使用。移动端界面调整导航、内容排布和操作区域，减少窄屏下的横向挤压；常用入口直接展示，其他模块可从“更多”进入。桌面端仍可使用完整工作台。

## 提交使用反馈

从反馈入口打开弹窗，填写遇到的问题或建议，最多 1000 字。字数按去除首尾空白后的 Unicode 码点计数，普通表情计作一个码点；提交后保留服务端确认结果。

访客提交反馈不需要模型访问口令，也不需要反馈管理口令。网页会自动获取短效表单票据，连同反馈内容、当前页面和设备类别提交；票据失效时需重新获取后重试。反馈不经过 DeepSeek，不会因提交建议而调用模型。

反馈按条写入私有仓库 `RosannaBebe/zonghe-ai-feedback` 的 GitHub Issues。服务端使用固定格式保存内容与元数据，对提及符号和代码围栏字符做可逆转义，避免把用户文字变成 GitHub 提及或正文结构。匿名提交响应不包含私有 Issue 链接；后台读取后将内容按普通文本展示。

## 查看反馈列表

反馈列表使用独立的反馈管理口令保护，与模型访问口令分开。获准管理的成员可使用专用口令查看列表，每页最多 20 条；符合反馈标记的 Issue 才会出现，Pull Request 不进入列表。

项目所有者的本地管理口令文件为 `server/反馈管理口令.local.txt`。该文件不应进入 Git 或网页部署产物；本文不记录口令值。只向获准查看反馈的成员提供管理口令。

## 服务端配置

- `FEEDBACK_GITHUB_TOKEN`：只授权目标私有仓库，所需权限为 Issues 读写；平台要求的只读 Metadata 权限可随仓库访问保留，不授予其他仓库或代码写入权限。
- `FEEDBACK_REPOSITORY`：设为 `RosannaBebe/zonghe-ai-feedback`。
- `FEEDBACK_ADMIN_TOKEN`：反馈列表专用管理口令，至少 24 个字符。
- `FEEDBACK_SIGNING_SECRET`：表单票据的 HMAC 签名秘密，至少 32 个字符。
- `ALLOWED_ORIGIN`：精确列出允许访问的网页来源，多个来源用逗号分隔，不含路径、通配符或末尾斜杠。

秘密变量只配置在服务端，不写入前端源码、GitHub 仓库、日志或本文档。GitHub Token 只供服务端读写反馈仓库，访客无需获得它。

`GET /api/feedback-ticket?requestId=UUID` 发放有效期 5 分钟的签名票据，并绑定请求编号与网页来源。`POST /api/feedback` 接收反馈，要求 `X-Feedback-Ticket` 请求头和空的表单诱捕字段。`GET /api/feedback?page=1` 通过 `Authorization: Bearer <反馈管理口令>` 查询列表。

## 适用边界与验证状态

服务端限制单次反馈为 1–1000 字、请求体不超过 8 KiB，并校验页面和设备类别。基础内存限流按服务实例内的来源 IP 统计：10 分钟内最多获取 20 次票据、提交 6 次反馈；管理列表每分钟最多查询 60 次。

重复提交采用请求编号、最近 100 条 Issues 查询以及单个运行实例内的锁和缓存尽力避免重复。不同运行实例之间没有原子唯一约束，因此不保证严格只写入一次；内存限流也不等同于完整的反滥用系统。适合参赛展示和小范围试用，扩大使用规模时应按实际需要补充持久化限流与唯一约束。

本轮后端已通过模拟 GitHub 响应的本地自动检查，覆盖字数、票据、鉴权、错误处理、重复提交和分页。本轮线上部署与云端回归结果待更新；本说明不将本地检查当作云端验证完成。
